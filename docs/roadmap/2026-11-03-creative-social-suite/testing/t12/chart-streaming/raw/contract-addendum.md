# Private T12 streaming codec proposal, 2026-11-06

Not promoted. Source app/tests and roadmap were untouched. Full T12 remains open: dataset ownership/revisions/references, editor, XLSX/connectors, charts, documents/presentations/whiteboards and Office exports are not implemented here. A 25 MB CSV codec is not editor integration or public import acceptance.

Server-only closed constructor profile: `inline` (default) preserves 2,097,152 input bytes and canonical JSON bytes; `dataset` permits 25,000,000 input bytes and 52,000,000 canonical UTF-8 JSON bytes. Unknown profile throws InvalidArgumentException. No arbitrary caller-supplied numeric limits. Future dataset service chooses the fixed dataset profile after authorization; HTTP clients must not select it. Canvas document budget stays 2 MiB: a large dataset will need a private resource reference, not embedding.

`importChunks(iterable $chunks, string $format = 'csv', bool $header = true): array` consumes only string chunks. Empty chunks are allowed. No filesystem/network/IO is performed in the service. Each complete chunk is charged before any byte is processed. UTF-8/BOM/CRLF/quotes may span chunks. UTF-8 validation is performed on complete fields; CRLF inside quoted fields becomes LF and bare CR fails. Strict quoting, row/column diagnostics including header record, 1000 data rows, 100 columns, 500-codepoint labels, 10000-codepoint cells, strict IDs/schema and lexical formulas remain. Partial EOF and BOM-only input fail as appropriate. Leading literal U+FEFF is preserved through quoted export.

`import(string ...)` wraps `importChunks([$text], ...)`. `exportChunks(array ...)` validates and yields complete records; `export(string ...)` collects them. CSV/TSV remains lexical interchange, without types/IDs or protection when external spreadsheets evaluate formulas; safe public download is still pending before handlers.

Canonical JSON size uses the original JSON flags. It counts fixed structure, IDs, labels and each cell encoding incrementally, rejecting before traversing a virtual 1 GB tail. It never builds a full JSON string for size checking. Canonical JSON means encoded byte size, not Unicode codepoint count. No truncation, implicit number/formula inference, or significant-space normalization.

Resource evidence: real 25,000,000-byte input is generated by 1000 rows x 100 columns, first 990 rows with 249 backslashes per cell, last 10 with 248. CRLF and separators complete exactly 25,000,000 bytes. Roundtrip checks complete SHA-256, bytes, shape, first/last fields, and +1 input rejection. Peak PHP allocator measurement is not OS RSS and does not prove HTTP/editor memory limits. Canonical 52,000,000/+1 is tested using bounded per-record native encoding for an independent byte calculation.
