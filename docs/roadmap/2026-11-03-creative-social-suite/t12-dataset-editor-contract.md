## Núcleo de edición y fidelidad

E1. Módulo puro `resources/js/Studio/dataset-table.js` y test `tests/frontend/studio-dataset-table.test.mjs`. Parser JSON conservador reconoce números como tokens decimales con su lexema original. No usar JSON.parse/JSON.stringify para transportar de nuevo valores numéricos de las tablas: no deben perder 0.0, -0.0 ni enteros mayores que Number.MAX_SAFE_INTEGER. Puede usarse JSON.parse para cadenas/metadatos seguros. Antes del parseo se cuentan bytes UTF8 en tramos acotados: parseDatasetTable admite como máximo52.000.000bytes de entrada (igual al archivoJSON de importación del servidor), además del presupuesto canónico52MB; whitespace/escapes excesivos pueden superar el primero aunque la tabla canónica quepa. parseDatasetPage admite8MiB de cuerpo: cubre las filas6MiB, columnas y metadatos acotados del servidor. Profundidad JSON máxima16; rechazar claves duplicadas. Estos límites son fijos y no se amplían desde datos del consumidor. Ninguna evaluación de fórmulas, código ni URLs.

API del núcleo acordada antes de integración: datasetNumber/cellType/cellText/cellFromInput; parseDatasetTable/validateDatasetTable/datasetTableChunks/blankDatasetTable; operaciones editDatasetCell/renameDatasetColumn/addDatasetRow/removeDatasetRow/addDatasetColumn/removeDatasetColumn/copyDatasetTable/replaceDatasetText/fillDatasetBlanks/transposeDatasetTable; previewDatasetConversion/applyDatasetConversion; createDatasetHistory; parseDatasetPage/createDatasetAssembler. Célula numérica es objeto inmutable {type:"number",raw:"0.0"}. Metadata usa enteros JS seguros; la etiqueta de número no convierte a Double para el transporte.

E2. Tabla cerrada columns[{id,label}], rows[{id,values}]. Valores editor: string/null o número etiquetado y lexema JSON válido/finito para PHP double, conservando lexema. Rechaza boolean, objetos/celdas, claves desconocidas/duplicadas, listas donde espera objeto, UTF16 suelto, controles salvo LF/TAB, IDs duplicados/inválidos, límites1000x100,500codepointslabel/10000celda,52.000.000B UTF8. Normalización no muta entrada. Aclaración de corrección B1/B2 antes del fix: los objetos/listas del módulo deben ser datos JSON propios y densos. Se rechazan getters/setters sin ejecutarlos e índices heredados/huecos; Object.isFrozen externo no es prueba de snapshot interno. Sólo se reutilizan filas/columnas capturadas y marcadas por el propio núcleo, manteniendo el uso compartido de datos internos. Esto no cambia el JSON aceptado por el servidor ni los exports del módulo. Importar CSV/TSV conserva strings; conversión numérica siempre explícita mediante tipo de celda/columna, previsualiza errores por fila y no aplica parcialmente.

E3. Parse/serialize tipado JSON de tabla fiel semántico y lexemas de números recibidos; serialize emite por filas/chunks para Blob multipart sin stringify de tabla entera. Validación de esquema al parsear. Ediciones por ID/índice comprobado conservan otros IDs/valores. Añadir/eliminar fila/columna, renombrar columnas, copiar tabla, buscar/reemplazar literal, rellenar vacíos y transponer con nuevos IDs cuando cambian entidades. Límites y tipos comprobados antes de devolver nueva tabla. Undo/redo acotado sin clonar52MB por pulsación: operaciones/estado estructural compartido o límite explícito de historial con información al usuario. No coerción silenciosa ni truncado.

Decisión de transposición previa a su implementación: conservar encabezados originales como valores de la primera columna nueva, etiquetada "Columna"; las otras columnas se etiquetan "Fila 1…N". Cada columna original pasa a fila nueva y todas las entidades reciben nuevos IDs. Con cero filas se conserva una columna de encabezados. Con más de99filas se rechaza: añadir la columna de encabezados superaría100columnas. Explicar esta transformación antes de aplicarla; undo recupera la tabla original. Rellenar vacíos distingue null de texto vacío mediante opción explícita. Historial máximo30pasos con estado estructural compartido, sin clonar52MB por pulsación.

E4. Página de transporte: parser de respuesta rows preserva tokens numéricos sólo en celdas; valida offsets/revision/sha y continuidad entre páginas. Reúne como máximo1000filas/100columnas, exige IDs únicos/revision+SHA/columnas idénticos y next_offset exacto progresivo, rechaza ciclo/saltos/respuesta inconsistente. Metadata integer segura; nunca mezcla revisiones al paginar. Una página6MiB no reduce límite de dataset. Metadatos y tableUI no cambian original hasta guardar.
